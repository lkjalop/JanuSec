  B. Inference Architecture

  Option 1: Online Per-Event Update (recommended for real-time detection)
  class TFTModel:
      def update(self, entity_id: str, features: Dict[str, Any]) -> float:
          # Append to rolling window buffer (e.g., last 24 hours of features)
          self._append_to_window(entity_id, features)

          # Run TFT inference on full window
          if len(self._windows[entity_id]) >= self.min_window_size:
              score = self.tft.predict(self._windows[entity_id])
          else:
              score = self._fallback_ewma(entity_id, features)  # Warmup period

          return score
  - Pros: Low latency (5-50ms per event), real-time scoring
  - Cons: GPU required for production (TFT inference is compute-heavy)
  - Throughput: ~100-200 events/sec/GPU (A10G instance)

  Option 2: Batched Scoring (recommended for cost-sensitive deployments)
  class TFTModel:
      def update(self, entity_id: str, features: Dict[str, Any]) -> float:
          # Buffer features in-memory; return EWMA proxy score
          self._buffer[entity_id].append(features)
          return self._ewma_score(entity_id, features)

      async def batch_score(self):
          # Run every 60 seconds; update entity scores in bulk
          for entity_id, feature_window in self._buffer.items():
              scores = self.tft.predict_batch(feature_window)  # GPU batch inference
              self._entity_scores[entity_id] = scores[-1]  # Latest score
  - Pros: Higher throughput (1000+ events/sec), cheaper (CPU-only workers + 1 GPU batch
  server)
  - Cons: 60-second scoring lag (not truly real-time)

  Recommended Hybrid: Use Option 1 for high-priority entities (critical assets, VIPs),
  Option 2 for long-tail (low-risk hosts)
