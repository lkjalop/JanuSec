  3. ✅ YARA SERVICE MATURITY

  Status: PRODUCTION-READY (src/api/yara_endpoints.py)

  Features Implemented:

  CRUD Operations:
  - POST /api/v1/yara/rules: Save/update rule with compile-time validation
  - GET /api/v1/yara/rules: List all saved rules with metadata
  - DELETE /api/v1/yara/rules?name=...: Delete rule by name
  - Rule metadata parsing from // meta: family=..., severity=..., mitre=T1059,... comments

  Scanning Endpoints:
  - POST /api/v1/yara/scan_path: Scan server-side file path
    - Safety: Base directory restriction (YARA_SAMPLES_DIR), absolute path gate (YARA_ALLOW_ABS_PATH)       
    - Size cap: YARA_MAX_SCAN_BYTES (default 25 MiB)
  - POST /api/v1/yara/scan_upload: Scan uploaded file (multipart/form-data)

  Concurrency Control:
  - Semaphore-based (asyncio.Semaphore) with YARA_MAX_CONCURRENT_SCANS (default 2)
  - Prevents resource exhaustion under load

  Size/Time Caps:
  - Size limit: YARA_MAX_SCAN_BYTES (default 25 MiB) - _cap_bytes_limit()
  - Timeout: YARA_SCAN_TIMEOUT_SECONDS - ThreadPoolExecutor-based timeout with 504 on expiry
  - Match limit: YARA_MAX_MATCHES_PER_FILE (default 100)

  Optional Mirroring:
  - Individual .yar files written to YARA_RULES_DIR (controlled by YARA_MIRROR_RULE_FILES)
  - Stale file cleanup on rule deletion

  Prometheus Metrics (guarded registration):
  - yara_scans_total{mode,outcome} - Scan counter (mode: path/upload, outcome: ok/error/timeout)
  - yara_scan_latency_seconds{mode} - Scan latency histogram
  - yara_matches_total{pack} - Match counter by rule pack (from meta)
  - Per-rule precision mode:
    - yara_rule_matches_total{rule} - Matches per rule
    - yara_rule_bytes_scanned_total{rule} - Bytes scanned per rule
    - yara_rule_timeouts_total{rule} - Timeouts per rule (approximate on scan timeout)
    - yara_rule_errors_total{rule} - Errors per rule (approximate on scan error)

  Decision Annotation (yara_endpoints.py:549-612):
  - If event_id provided, attach factors to existing decision:
    - malware:yara_match_{rule_name}
    - Metadata-derived: threat:family:{family}, risk:{severity}, mitre:{technique}
  - Re-record decision to SSE stream and persistence

  Hash Reputation Check (yara_endpoints.py:646-672):
  - SHA256 hash lookup against threat intel client
  - Attach reputation:hash_known_bad factor if matched

  MITRE Technique Counting:
  - Rule meta mitre=T1059,T1105 parsed and emitted as factors
  - Counted in ingestion report "Top MITRE Techniques"

  4. ✅ SBOM AND VEX WORKFLOW

  Status: FULLY IMPLEMENTED (src/api/sbom_endpoints.py, src/integrations/vuln_enrichment.py)

  Endpoints:

  POST /api/v1/sbom/upload:
  - Accepts CycloneDX/SPDX-ish JSON: {sbom_id?, components:[{name,version,purl?,cpe?}]}
  - Heuristic vulnerability mapping (log4j, openssl 1.0/1.1, struts)
  - Returns {sbom_id, components, vulns_found}

  GET /api/v1/sbom/vulns?sbom_id=...&include_suppressed=false:
  - Returns vulnerabilities with KEV/EPSS enrichment (via ENRICHER)
  - VEX filtering applied dynamically:
    - Matches by component + CVE + version range
    - Statuses: not_affected, fixed, under_investigation, affected
    - not_affected → suppressed=True, severity=none, risk_score=0.0
    - fixed → severity=low, risk_score reduced
  - Default: suppressed vulns excluded unless include_suppressed=true

  POST /api/v1/sbom/vex:
  - Attach VEX statements: {sbom_id, 
  statements:[{component,cve,status,justification?,notes?,version_range?}]}
  - Version-range support: >=1.2.0,<2.0.0 style constraints
  - Persistence: Append-only JSONL at data/sbom_vex.jsonl

  KEV/EPSS Enrichment (src/integrations/vuln_enrichment.py):

  - KEV cache: TTL-based, disk-persisted (data/kev_cache.json)
  - EPSS cache: TTL-based, disk-persisted (data/epss_cache.json)
  - Fields added: kev (bool), epss (float), exploit_available (bool), risk_score (adjusted)
  - Conditional GET: ETag/Last-Modified headers for efficient refresh

  Version Range Parsing (sbom_endpoints.py:53-102):

  - Supports: >=, <=, >, <, ==, =
  - Comma-separated constraints: >=1.2.0,<2.0.0
  - Tuple-based version comparison

  Frontend Integration:
  - SBOM page (frontend/static/sbom.html): Upload SBOM, view vulns with include_suppressed toggle, add      
  VEX statements with version range input

  Code Reference: src/api/sbom_endpoints.py:1-243, src/integrations/vuln_enrichment.py
